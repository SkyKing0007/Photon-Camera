PHOTON / IRIS DEVELOPMENT STRICT RULES — 26529 V3 AND FORWARD
================================================================

BJZHOU / MGC REFERENCE RULE — STRICT
- bjzhou/MGC source is a pinned behavioral and mathematical reference only.
- Never copy a bjzhou runtime implementation wholesale into Iris merely to obtain parity.
- Iris must preserve its own rewritten architecture, owners, GPU lifecycle, buffers, Motion
  pipeline, metadata domains, CFA geometry, exposure authority, DNG/UHDR behavior, and prior fixes.
- Compare semantics: equations, constants, stage ordering, coordinate domains, CFA phase handling,
  weighting, clipping, rejection/admission semantics, texture/data domains, boundaries, and
  producer-consumer ownership.
- A bjzhou commit/blob SHA may pin provenance, but an Iris validator must NOT require an Iris
  runtime file to equal the bjzhou blob. The validator should explicitly prove the runtime is an
  Iris rewrite and audit semantic counterparts instead.
- Vendoring unchanged third-party dependencies is a separate exception only when explicitly
  intended (for example the already-established native dependency bootstrap used by 26528).

HANDOFF / BUILD VALIDATION RULE — STRICT
- Use the exact successful predecessor candidate artifact as runtime authority; repository app/src
  is not runtime authority for these candidate-reconstruction builds.
- Resolve the complete transform before candidate writes.
- Generate and hash forward AND rollback patches before candidate writes.
- The handoff must contain certified expected forward/rollback patches and hashes.
- The workflow must regenerate both patches and compare them byte-for-byte with the certified ones.
- Run independent semantic validation, protected-file checks, shader/native/DNG checks, and inherited
  architecture checks before PRE-BUILD SAFETY PROOF PASSED.
- Increment VERSION_NAME/VERSION_BUILD only inside the same guarded block that runs Gradle.
- Hash audited runtime before and after Gradle and fail if Gradle mutates it.
- Reconstruct/scrub the postbuild runtime exactly as the successful predecessor procedure does,
  rerun validators, require exactly one APK, and emit a deterministic next-candidate source archive.
- A compile success alone is never sufficient to declare a handoff safe.

BACKUP POLICY
- No routine backup branch. Exact predecessor candidate + certified rollback patch is the normal
  recovery mechanism unless an exceptional operation explicitly requires a branch backup.
