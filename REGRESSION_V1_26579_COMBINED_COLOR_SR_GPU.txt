DEVICE FAILURES THAT MOTIVATE THIS BUILD

A. Shared normal + Super Res micro-color loss
- On successful 26578, the tiny circular world-flag prints are visibly desaturated in BOTH the normal 12MP image and the Super Res image.
- Therefore the primary color-loss failure is shared/upstream of the SR-only upsampler.
- The successful 26578 neutral false-chroma cleanup must not be backed out to restore those colors.

B. Additional Super Res chroma/font degradation
- Super Res retains real high-resolution luma/detail evidence, but its native-resolution VGN guide chroma was enlarged with simple four-sample bilinear interpolation.
- Cross-material bilinear mixing can dilute a tiny real colored print against white paper and can spread any surviving neutral-edge chroma around black text.
- direct-CFA chroma ownership is forbidden; SR may only reconstruct from already-supported native VGN chroma.

C. GPU publication falls back before useful 50MP publication work
- Successful 26578 device trace: true2x reconstruction backend=GPU, size=8192x6144, reconstruction=18495ms.
- The publication stage still reports backend=CPU gpuEligible=1 gpuUsed=0.
- Async GPU attempt fails in about 453.728ms with missing_async_reason.
- Map-sync compatibility GPU attempt fails in about 442.264ms with missing_compat_reason.
- CPU save/publication then costs about 32978ms.
- The exact old wrapper has early output-file failure paths that return false without propagating the reason.
- The old GPU-only sibling naming appends .iris26571_gpu after a Java-authorized .jpg intermediate, changing the terminal extension and creating an unnecessary external-storage target not owned by the Java publication contract.
- The successful 26578 CPU fallback proves native fopen/write succeeds on the exact Java-authorized .true2x.base.jpg / .true2x.gain.jpg targets; 26579 reuses those proven targets instead of inventing another sibling filename.

REQUIRED 26579 COLOR BEHAVIOR

1. Inherit all 26578 fail-closed protections unchanged.
2. compact multicolor printed objects are protected by 2-D chroma occupancy even when adjacent real colors do not share one hue.
3. A real micro-object must show chromatic support distributed in both X and Y / non-collinear area support; a thin edge-following chromatic ribbon must not earn this veto merely by being saturated.
4. Strong Bayer-like near/far phase behavior suppresses the new micro-object veto so the exact inherited neutral purple/green false-fringe failure remains correctable.
5. Colored text/contours, tiny saturated objects, and foliage/sky remain protected.
6. Ambiguous color remains untouched. No global saturation increase is allowed.

REQUIRED 26579 TRUE2X CHROMA BEHAVIOR

1. true2x flow/refinement/alignment math is byte-identical to successful 26578.
2. highResLumaOwner remains DIRECT_CFA; directChromaOwner remains false.
3. Native VGN RGB remains the sole true2x chroma authority.
4. Replace only cross-material bilinear chroma interpolation with same-material/topology-aware weighting using native guide luma similarity and high-resolution luma-side evidence.
5. Flat colored surfaces must remain exact bilinear/pass-through.
6. Neutral black/white glyphs must remain neutral; SR must never invent chroma.
7. Output SR chroma magnitude must never exceed the strongest supported native VGN chroma among the local source samples.
8. Luma/detail must remain owned by the existing direct-CFA factor; the new chroma reconstruction must not sharpen, move, or repaint geometry.
